GymFlow V1 interfaces

Four focused workspaces. One connected system.

Fictional demonstration data

Member workspace: personal membership, attendance, sessions, workouts, payments and progress.

Case study

Problem
Gym operations are often split across paper records and disconnected tools, making memberships, attendance, schedules and payments difficult to coordinate.
Solution
A single role-aware workspace for owners, receptionists, trainers and members, with each role limited to the information and actions it needs.
My role
Designed and developed the application structure, interfaces, API workflows, database migrations, access rules, tests and project documentation.
Architecture
React and TypeScript public showcase with browser-local fictional data; modular Python JSON API, ordered SQL migrations, SQLite development storage and PostgreSQL production support in the complete V1.
Challenge
Protecting role boundaries and membership integrity while supporting renewals, attendance, schedules, reporting and safe payment simulations.
Result
A live, actively maintained four-role showcase backed by a documented end-to-end V1 with automated tests, recovery tooling and access controls.
